## 对 PM-05 R1 的确认

- **缺口**：`users.openid`（V1 迁移第 30、46、57 行）与 `file_objects.object_key`（V2）、`orders.client_request_id`（V3）未做列级 `COLLATE` 覆盖，继承表级 `utf8mb4_0900_ai_ci`，导致唯一键与等值比较**大小写不敏感**。同一用户的不同大小写 openid 会被 `uk_users_openid` 视为重复；`object_key`、`client_request_id` 同理。

- **对下游的约束**：**BE-04 不得基于当前未修订的身份比较逻辑上线或验收**——在 V6 落地前，任何以 `openid` 唯一性或大小写敏感性为前提的实现与验收均不成立。

## 关键规则

- 权限：本任务不实现接口与权限，仅建立结构。`users.role`/`users.status` 的取值集合由 CHECK 约束限定。
- 事务：迁移只建结构与写种子，无业务事务。
- 状态与幂等：Flyway 按版本执行，已执行版本永久只读；迁移脚本不写 `INSERT IGNORE`/`ON DUPLICATE KEY UPDATE`。
- 外键：不使用级联删除，历史数据由 `ON DELETE RESTRICT` 保护。

## 未由数据库强制、留给应用层的规则

1. 同一用户只能有一个 `PENDING` 认证申请（MySQL 无部分唯一索引；`certifications` 只有普通索引与用例查询）。**仅靠“先查后写”在并发下不足**：认证模块必须先用 `SELECT ... FOR UPDATE` 锁定该用户行再校验并写入。责任任务 BE-05。
2. 同一商品只能存在一个活动订单（`PENDING_CONFIRMATION` / `CONFIRMED` / `PENDING_RECEIPT`），由商品乐观锁 + 订单查询二次校验实现。
3. 分类只能两级，且不得把自身或后代设为父级。
4. 商品图片总数 1～9（数据库只限制 `item_images.sort_no` 在 1～9）。
5. 一级分类同名（`parent_id IS NULL` 时 `uk_categories_parent_name` 因多个 NULL 而不生效）。
6. `order_snapshots`、`order_events`、`audit_logs` 的“只追加”语义。**该语义是应用层约定，不是数据库强制**：迁移 SQL 未撤销这些表的 UPDATE/DELETE 权限，也没有触发器阻止修改。应用层不得为它们提供更新/删除用例；历史保留通过业务状态（如 `reviews.status`）而非物理删除实现。如需数据库级强制，须另开任务评估权限或触发器方案。
7. `users.average_rating`/`users.review_count`、`items.view_count`/`items.favorite_count` 的汇总一致性。
8. 订单状态机与商品状态的联动（下单锁商品、取消释放、收货置 `SOLD`）必须在同一事务内完成。
9. 认证状态与 `users.certification_status` 的同步。

## 后续 Entity 映射必须注意的类型与生成列

> **须用 `validate` 复核**：以下类型建议来自 DDL 静态阅读，**尚未经任何 Entity 实测**。BE-03 起配置 `spring.jpa.hibernate.ddl-auto=validate`，以启动时的实际校验结果为准。**若校验失败，修正 Entity 或 `columnDefinition`，不得修改 V1～V5 迁移来迁就校验**（已执行版本永久只读）。

- **无生成列**：15 张表都没有 `GENERATED ALWAYS AS` 计算列。唯一的数据库生成值是 `AUTO_INCREMENT` 主键，JPA 应使用 `@GeneratedValue(strategy = GenerationType.IDENTITY)`。`order_snapshots` 的主键 `order_id` **不是**自增，由订单 ID 赋值，禁止加 `@GeneratedValue`。
- **`BIGINT UNSIGNED`**：Java 侧统一用 `Long`（不要用 `Integer`）。注意 Java 无无符号语义，`Long` 只能表示到 `Long.MAX_VALUE`；上界差异在本项目数据量下不构成问题。
- **`INT UNSIGNED`**（`users.review_count`、`items.view_count`、`items.favorite_count`、`categories.sort_no`）：Hibernate 无无符号类型，建议映射为 `Long`（或 `Integer`，需自行保证不超过 21 亿）。
- **`TINYINT UNSIGNED`**（`item_images.sort_no`、`reviews.rating`）：映射为 `Short` 或 `Integer`，不要用 `Byte`（会丢 128～255 段）。
- **`TINYINT(1)`**（`items.admin_lock`）：映射为 `Boolean`；如 Hibernate 方言推导为 `TINYINT`，需显式 `columnDefinition = "TINYINT(1)"`。
- **`DATETIME(3)`**：全部时间列。JPA 默认推导为 `TIMESTAMP`（精度可能丢失毫秒），建议显式 `columnDefinition = "DATETIME(3)"`；Java 用 `LocalDateTime`。
- **`created_at`/`updated_at`（`NOT NULL`，无数据库默认值、无 `ON UPDATE`）**：JPA 必须通过 `@PrePersist`/`@PreUpdate` 或 `JpaAuditConfig`（`@EnableJpaAuditing`）显式赋值；否则 INSERT/UPDATE 会因 NOT NULL 失败。**注意**：`order_snapshots`、`order_events`、`notifications`、`audit_logs`、`favorites`、`item_images`、`file_objects`、`refresh_tokens` 只有 `created_at` 或没有 `updated_at`，不要给所有实体套用同一个“创建/更新审计基类”。
- **`DECIMAL(10,2)` / `DECIMAL(3,2)`**：Java 用 `BigDecimal`；`users.average_rating` 为 `DECIMAL(3,2)`（标度 2、精度 3）。
- **`JSON`**（`audit_logs.detail_json`）：映射为 `String`，或使用 `@JdbcTypeCode(SqlTypes.JSON)` + `String`/`Map`。
- **`CHAR(64)`**（`refresh_tokens.token_hash`、`file_objects.sha256`）：映射为 `String`；`CHAR` 会右补空格，写入必须是定长 64 位十六进制。
- **枚举列（`VARCHAR(32)`）**：一律 `@Enumerated(EnumType.STRING)`，禁止 `ORDINAL`。
- **`version` 列**：`users`/`items`/`orders` 有 `BIGINT NOT NULL DEFAULT 0`，用 `@Version private Long version;`。其余表无版本列，不要加 `@Version`。
- **无 `deleted` 列**：不要配置 Hibernate 软删除（`@SQLDelete`/`@Where`）；商品删除是 `items.status` 状态变更。
