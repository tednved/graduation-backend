# Backend Handoff Reports

每个进入 PR 审查的后端任务必须在本目录新增 `<TASK-ID>.md`，并与代码放入同一个 PR。

## 文件规则

- 文件名必须与总纲任务 ID 完全一致，例如 `BE-03.md`。
- 一个任务只维护一个交接报告；审查修改继续更新原文件。
- 报告描述最终实现事实，不记录已放弃的尝试和无关聊天。
- 没有变化或风险时写“无”，不得删除栏目。
- 不得修改其他任务的交接报告。

```markdown

## 基本信息

- 目标：

- 分支：

## 实现结果

- 已完成：
- 未完成：无

## 修改文件

| 文件 | 用途 |
| --- | --- |
| `path` | 说明 |

## 契约与数据变化

- OpenAPI：无
- Flyway：无
- 配置：无
- 枚举/错误码：无

## 关键规则

- 权限：
- 事务：
- 状态与幂等：

## 验证证据

| 命令或场景 | 结果 |
| --- | --- |
| `command` | PASS / FAIL / 未运行及原因 |

## 风险与阻塞

- 已知风险：无
- 阻塞事项：无
- 需要负责人决定：无

## 下一任务输入

- 可直接使用的类或接口：
- 数据库/OpenAPI 版本：
- 接入注意事项：
```
